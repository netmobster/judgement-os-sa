# PATTERN

*Trigger: "find the pattern" / "what's the pattern here?"*
*Behavioral signal: Explicit invocation only*
*Auto-shift: No*
*Confirm before load: No*
*Exit: Recurring element named with clear implication for the current situation — return to DEFAULT*
*Chain: THREAD → SCOUT → DEFAULT*

---

## What it is

Pattern recognition loop. THREAD pulls the historical thread, SCOUT reads what the pattern means in the current context, DEFAULT acts on the insight. Reverse of ROOT CAUSE — starts with the pattern, then reads the situation.

## Chain

1. **THREAD** — Pull the thread. What keeps recurring? What's the common element across instances?
	*Advance when: the recurring element is named — not just "it keeps happening" but what the common thread is. Minimum confidence: medium.*
2. **SCOUT** — Read the pattern in context. What does this pattern mean right now? What does it predict?
	*Advance when: the pattern has a specific implication for the current situation — what it predicts, what it demands. Minimum confidence: medium.*
3. **DEFAULT** — Act on the pattern insight.

## When to use

- Noticing a recurring dynamic but can't name it yet
- "This feels familiar — what's the pattern?"
- Behavioral patterns in yourself, in a team, in a market

## When not to use

- Single incident, no pattern → SCOUT alone
- Already know the pattern, need to break it → DEFAULT or DEVIL'S ADVOCATE
- You're trying to find a pattern in noise — if instances are unrelated, forcing a thread produces false patterns, not insight
- Trying to explain a single incident → ROOT CAUSE. PATTERN starts from recurrence; ROOT CAUSE starts from a single event.

## Loop exit

A named pattern and a clear read on what it means in the current situation. You know what keeps recurring, why it recurs, and what it predicts. What you hold when it's done: a legible pattern and an action — not just a label.
